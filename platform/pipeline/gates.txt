# gates.txt — THE registry of machine-readable gate results.
#
# WHY THIS FILE EXISTS
# Every stage of this pipeline reports by printing `<TOKEN>_RESULT: <VERDICT>` and every consumer
# reads that by hand-writing `grep -q '<TOKEN>: PASS'`. There were 18 tokens and 15 such greps, and
# nothing anywhere listed them. On 2026-09-06 a third verdict word (DEBT) was added to VERIFY_RESULT
# and the plate was refused by handoff.sh exit 14; that was fixed, and the plate was then refused
# one gate later by qualification_check.py, which held the same rule independently. Two gates had
# reached the same conclusion separately and the only way to find the second was to hit it. There
# was no list to check the change against — so this is the list.
#
# The registry is only worth trusting because it cannot drift: test_gates.py asserts that every
# token emitted or scraped anywhere in the tree appears here, that each row's emitter really emits
# it, and that each declared exit code really appears in the file said to enforce it. Add a token
# without a row and the suite fails.
#
# COLUMNS
#   token        the literal printed before the colon
#   passing      verdicts that are unconditionally OK (comma separated)
#   conditional  verdicts OK only when `condition` holds; blocking otherwise
#   condition    what must hold for `conditional`, or - when there is none
#   exit         exit code the enforcing caller uses when this gate blocks, or - if it only reports
#   bypass       env var that overrides, or `none` — `none` means no bypass exists, by design
#   emitter      the file that prints the token
#   enforced_as  the argv the enforcing caller uses THAT CHANGES THE VERDICT, or - when running it
#                bare answers the same question the gate does
#
# `enforced_as` exists because a checker's verdict can depend on its flags, and running it by hand
# then answers a DIFFERENT question than the gate does — in both directions. Bare
# platform_boundary.py is STRICTER than the hook and produced a false "the commit is blocked" that
# survived three sessions; bare dim_provenance.py is LOOSER than the handoff and would produce the
# opposite error, a green that the gate will refuse. Any row whose enforced_as carries a flag must
# have its emitter call gates.declare_mode(), and test_gates.py enforces that.
#
# Only STRICTNESS flags belong here, never flags that merely supply input. postprocess.py --gcode
# names the file to read and gives the same verdict either way, so its row is `-`; support_check.py
# --meta is the opposite — without it no keep-outs are loaded and the run is quietly LOOSER than
# the gate, which is exactly the case worth announcing. Note --meta, not --spec: slice_meta.json
# carries the spec path and support_check falls back to it (`spec_path or meta.get("spec")`), so
# --meta alone reproduces the gate. This row said --spec until a live verify-slice run printed
# "NOT THE GATE" while being, in fact, the gate — the registry was wrong, not the code.
#
# Any verdict not listed in `passing` or `conditional` blocks. That default is deliberate: a new
# verdict word is refused until somebody decides here what it means.
#
# token | passing | conditional | condition | exit | bypass | emitter | enforced_as
